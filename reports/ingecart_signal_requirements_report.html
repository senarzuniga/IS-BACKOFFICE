Requerimientos mínimos de señales para monitorización industrial

Este informe define el conjunto mínimo de señales necesarias para que la monitorización de máquinas de Ingecart y de terceros sea viable en el modelo de paneles de Smart Plant Dashboard, con foco en soporte, mantenimiento, producción, OEE y servicio técnico.

1. Objetivo

No hace falta pedir todas las señales disponibles del equipo. El objetivo es obtener el mínimo conjunto útil que permita:

  • Conocer si la máquina está en marcha o parada.
  • Medir rendimiento, OEE y flujo de producción.
  • Detectar averías, bloqueos y riesgos.
  • Soportar mantenimiento preventivo y correctivo.
  • Permitir diagnóstico por parte de ingeniería y servicio.

2. Principio de diseño: mínimo viable profesional

Señales mínimas por equipo

  • Estado de máquina
  • Producción real / throughput
  • Alarmas y fallos activos
  • Temperatura / corriente / potencia
  • Tiempo de parada
  • Runtime desde mantenimiento
  • Heartbeat PLC / comunicación
  • Estado seguridad / E-stop

Señales “muy recomendables”

  • Vibración
  • Eventos históricos
  • Contadores de piezas, pallets o reels
  • Signal quality / scrap
  • Buffer / cola / nivel / material presente
  • Recipe, orden actual y operador
  • Posición o destino de AMR / transfer
  • Batería / carga / estado de movilidad

3. Requerimiento para Ingeniería Eléctrica

Área Señales Objetivo
Alimentación y seguridad Alimentación principal OK / NO OK, breaker, contactor, E-stop, guardas, interlocks Detectar disponibilidad y seguridad
Potencia y consumo Tensión, corriente, potencia activa, consumo eléctrico, overload Diagnóstico eléctrico y benchmarking energético
Condición mecánica / térmica Temperatura motor, caja, tablero, zona crítica; vibración Riesgo de avería y mantenimiento predictivo
Sistemas móviles Batería, UPS, tensión, estado de carga, alarmas de energía Disponibilidad de AMR y equipos móviles

Lo mínimo útil que debe pedir Ingeniería Eléctrica

  • machine_power_ok
  • motor_running
  • current_or_power
  • temperature_c
  • vibration_mm_s
  • overload_alarm
  • estop_or_safety_fault
  • battery_pct (si aplica)

4. Requerimiento para Ingeniería de Software / Automatización

Área Señales Objetivo
Estado de máquina running, stopped, idle, fault, maintenance, blocked, starved Control operativo y dashboard
Producción throughput_per_hour, good_units, scrap_units, rejects OEE y rendimiento
Paradas downtime_minutes, reason_code, fault_code, last_alarm Diagnóstico y soporte
Mantenimiento runtime_since_pm, pm_due, mantenimiento pendiente Preventivo y servicio
Integración heartbeat PLC, order_id, recipe_id, operator_id, event_timestamp Traza de eventos y análisis

Lo mínimo útil que debe pedir Ingeniería de Software

  • machine_state
  • running
  • throughput_per_hour
  • good_units
  • scrap_units
  • downtime_minutes
  • alarm_code
  • fault_present
  • runtime_since_pm
  • heartbeat
  • last_event_time

5. Señales mínimas por familia de equipo

Tipo Señales clave
Palletizer estado, ciclos/hora, piezas/pallet, seguridad, temperatura, vibración, parada por jam, alarmas
Conveyors / transfercar estado cinta, velocidad, material presente, jam, cola/buffer, temperaturas, alarmas
AMR / AGV estado, posición, destino, batería, tensión, carga, gripper, alarma de navegación, heartbeat
Weighing peso medido, status, out-of-range, alarmas, calibración
RFID / tracking lectura OK/KO, ID pallet/reel, lecturas/hora, zona de paso, errores
Ingetrans / reels ID reel, estado entrega/recogida, carril/posición, RFID, alarmas, throughput
BHS / sheet handoff estado entrega, WIP disponible, pallet full/empty, handoff OK/NOK, alarma robot

6. Recomendación mínima viable para Smart Plant Dashboard

El conjunto ideal para cubrir la mayoría de casos es esta lista base, aplicable a prácticamente cualquier activo:

  • machine_state
  • running
  • throughput_per_hour
  • good_units
  • scrap_units
  • downtime_minutes
  • alarm_code
  • fault_present
  • temperature_c
  • current_or_power
  • vibration_mm_s
  • runtime_since_pm

Con esta base se puede sostener OEE, alertas, troubleshooting, mantenimiento, soporte técnico y servicio sin sobrecargar la integración ni el proyecto de ingeniería.

7. Recomendación final

Prioridad 1 Estado operativo + producción + alarmas + tiempo de parada.

Prioridad 2 Temperatura, vibración, corriente y runtime desde PM.

Prioridad 3 RFID, ubicación, batería, eventos históricos y order/recipe context.

8. Resumen ejecutivo

La monitorización funcional para Smart Plant Dashboard no exige “todas las señales”. Se necesita un conjunto mínimo, consistente y accionable que permita ver estado, rendimiento, disponibilidad y salud. Ese conjunto debe entregarse en dos capas: Ingeniería Eléctrica (energía, protección, temperatura, vibración, seguridad) y Ingeniería de Software (estado, producción, alarmas, eventos, maintenance, heartbeat, orden y flujo). Esta combinación es la base para un soporte adecuado, una monitorización serena y un servicio más profesional para Ingecart y para clientes terceros.
