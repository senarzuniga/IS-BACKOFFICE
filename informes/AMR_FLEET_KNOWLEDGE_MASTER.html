🤖 Fleet Manager Core
El núcleo operacional del sistema. Gestiona el estado de todos los robots en tiempo real y ejecuta el control de tráfico y despacho de misiones.
Responsabilidades
  • Estado flota en tiempo real
  • Control de tráfico (traffic controller)
  • Despacho de órdenes VDA5050
  • Gestión de charging
  • Alarms y health
Interfaces
  • VDA5050 MQTT (robots)
  • REST API (clientes)
  • WebSocket (dashboard)
  • OPC-UA (PLCs)
Stack Técnico
  • Python / FastAPI
  • Redis (state cache)
  • PostgreSQL (persistence)
  • Eclipse Mosquitto (MQTT)
SLAs
  • Control loop: <100ms
  • Replanning: <200ms
  • Uptime: 99.9%
  • Robots max: 500+
🎯 Mission Manager
Orquestador de alto nivel de misiones. Recibe órdenes de negocio (WMS/MES) y las traduce en misiones ejecutables para la flota. Gestiona prioridades, dependencias y excepciones.
Tipos de Misión
  • TransportMission (A→B)
  • PickMission (recoger)
  • DropMission (depositar)
  • ChargeMission (cargar)
  • InspectionMission
  • EmptyWasteMission
  • RestockMission
Priority Levels
  • CRITICAL (0): corrugadora sin material
  • HIGH (1): convertidora hambrienta
  • NORMAL (2): transporte estándar
  • LOW (3): reposición consumibles
  • IDLE (4): optimización energética
States
  • PENDING → QUEUED
  • QUEUED → ASSIGNED
  • ASSIGNED → IN_PROGRESS
  • IN_PROGRESS → COMPLETED
  • ANY → FAILED / CANCELLED
🗺️ Layout Intelligence
Gestión inteligente del layout de la planta. Mantiene el mapa de navegación actualizado, gestiona zonas, identifica cuellos de botella y propone optimizaciones de layout.
Factory Graph
  • Nodos: puntos de interés
  • Aristas: segmentos de ruta
  • Zonas: agrupaciones lógicas
  • Atributos: velocidad, prioridad, anchura
Tipos de Zona
  • HIGHWAY: carril principal
  • BUFFER: zona WIP
  • DOCK: punto carga/descarga
  • CHARGING: estación carga
  • RESTRICTED: solo robots autorizados
  • PEDESTRIAN: reducir velocidad
Live Updates
  • Block/unblock zones en tiempo real
  • Recalibración de mapas SLAM
  • Detección de cambios de layout
  • Propagación a todos los robots
🧠 Knowledge Graph + Factory Graph
Representación semántica del conocimiento de la planta. Relaciona materiales, máquinas, procesos, robots, zonas y órdenes en un grafo de conocimiento consultable que alimenta las decisiones del sistema.
Entidades
  • Material (WIP, bobina, pallet)
  • Máquina (corrugadora, conv-X)
  • Robot (tipo, estado, posición)
  • Zona (tridente, highway, dock)
  • Pedido (cliente, urgencia, FEFO)
  • Útil (cliché, troquel, tinta)
Relaciones
  • Material DESTINO_A Máquina
  • Robot ASIGNADO_A Misión
  • Material ALMACENADO_EN Zona
  • Pedido REQUIERE Útil
  • Misión BLOQUEADA_POR Misión
  • Robot COMPATIBLE_CON Payload
Tecnología
  • Neo4j o Memgraph (graph DB)
  • Cypher queries para decisiones
  • GraphQL API para consultas
  • Actualización en tiempo real
🔮 Digital Twin + Simulation Engine
Réplica virtual de la flota y la planta en tiempo real. Permite validar cambios antes de aplicarlos, simular escenarios alternativos y entrenar modelos de IA sin riesgo.
Capacidades
  • Réplica estado flota (sync RT)
  • Simulación de escenarios alternativos
  • Validación de cambios de layout
  • Test de nuevas reglas de negocio
  • Entrenamiento modelos IA offline
Métricas Simuladas
  • Throughput estimado
  • Tiempo ciclo por flujo
  • Utilización de robots
  • Congestión por zona
  • Consumo energético
Tecnología
  • SimPy (discrete event sim)
  • 3D visualization: Three.js
  • Real-time sync via WebSocket
  • Histórico: TimescaleDB
📚 Mission Knowledge Package
KP-001 · Arquitectura de Referencia: VDA5050 como núcleo de comunicación
VDA5050 v3.0 es el estándar de facto para comunicación Fleet Manager ↔ Robots. Adoptar VDA5050 como protocolo nativo en ING_DIGHUB FMS garantiza interoperabilidad con cualquier fabricante de AMR/AGV del mercado. El protocolo define 6 tópicos MQTT con semántica clara. Fuente: GitHub VDA5050/VDA5050 (470 stars, VDA+VDMA oficial). Confianza: ALTA.
KP-002 · Patrón Highway Architecture para layouts lineales
Para plantas con layout lineal >50m (como INGECART 120m), el patrón Highway con Carril A (→) y Carril B (←) es el óptimo. Maximiza throughput, previene conflictos y simplifica el Traffic Controller. Los robots solo pueden ir hacia adelante en su carril, eliminando gran parte de los escenarios de deadlock. Accesos laterales a tridentes/docks interrumpen momentáneamente el carril → diseñar con pendientes de acceso. Fuente: análisis INGECART. Confianza: ALTA.
KP-003 · Carga inductiva = ventaja competitiva decisiva
La carga inductiva (sin contacto) elimina la necesidad de paradas programadas para carga. El robot se carga mientras espera en puntos de carga instalados en el suelo de zonas de espera. Resultado: disponibilidad 99% demostrada por KUKA en producción. Para INGECART, instalar cargadores inductivos en los extremos del highway (zonas de espera naturales). Coste adicional: ~15% sobre precio robot. ROI inmediato por eliminación de paradas. Fuente: KUKA AMR product. Confianza: ALTA.
KP-004 · Pre-staging proactivo = mayor ROI en convertidoras
El mayor impacto económico de un Fleet Manager en plantas con convertidoras no es el transporte de WIP, sino el pre-staging proactivo de útiles de cambio de pedido. Al conocer la secuencia de producción del MES, el Fleet Manager puede anticipar el kit necesario 20-30 minutos antes del cambio. Esto reduce el tiempo de changeover un 40-60%. Caso validado: cualquier planta de cartón corrugado con múltiples convertidoras. Fuente: análisis industrial. Confianza: ALTA.
KP-005 · La corrugadora es el constraint: prioridad CRÍTICA
En cualquier planta de cartón corrugado, la corrugadora es el cuello de botella principal y el activo más costoso. Una parada de la corrugadora por falta de material (bobina) o por acumulación de WIP sin evacuar cuesta >€1.000/hora. El Fleet Manager DEBE implementar una prioridad CRÍTICA (nivel 0) para cualquier misión relacionada con la corrugadora: suministro de bobinas y evacuación de WIP. Estas misiones interrumpen cualquier otra misión en curso. Fuente: industria corrugado. Confianza: ALTA.
KP-006 · Reserva de segmento = clave anti-deadlock
El mecanismo de reserva de segmento de ruta (antes de que el robot entre) es la forma más efectiva de prevenir deadlocks en flota AMR. El robot solicita reserva del segmento siguiente antes de entrar. Si no puede reservar → espera en wait-zone. Si el wait-zone está ocupado → replanning por ruta alternativa. Este patrón se implementa eficientemente con el Reservation Manager microservice. Fuente: VDA5050 spec + tráfico analysis. Confianza: ALTA.
KP-007 · No-code commissioning = acelerador de adopción
KUKA.AMR Suite demuestra que el comisionado no-code (drag&drop) es un diferenciador clave para la adopción industrial. Los ingenieros de planta pueden configurar y modificar rutas sin programar, incluso durante la producción. ING_DIGHUB debe implementar una interfaz equivalente como parte del Layout Intelligence. El tiempo de configuración inicial se reduce de semanas a días. Fuente: KUKA AMR Suite product. Confianza: ALTA.
KP-008 · Flotas heterogéneas son la norma en plantas maduras
Las plantas industriales raramente tienen un solo tipo de robot o un solo fabricante. Los Fleet Managers que solo soportan su propio hardware son un lock-in inaceptable. VDA5050 soluciona esto: ING_DIGHUB FMS debe ser agnóstico de fabricante desde el día 1. La arquitectura correcta es: capa de abstracción VDA5050 + adaptadores para protocolos propietarios legacy. Fuente: KUKA AMR Fleet + análisis mercado. Confianza: ALTA.

⚖️ Decision Registry

DR-001: VDA5050 como protocolo nativo

  • Decisión: Adoptar VDA5050 v3.0 como protocolo estándar
  • Alternativas: ROS2 Actions, protocolo propietario
  • Score VDA5050: 95/100
  • Score ROS2: 71/100
  • Razón: Estándar industrial, interoperabilidad máxima, soporte institucional VDA+VDMA

DR-002: On-premise para Fleet Manager Core

  • Decisión: Fleet Manager Core on-premise + Analytics cloud
  • Alternativas: Full cloud, full on-premise
  • Score híbrido: 88/100
  • Score full cloud: 62/100
  • Razón: Latencia crítica para control de tráfico. Analytics no es crítico en tiempo

DR-003: Flota de 15 AMR para INGECART

  • Decisión: 15 AMR (3 heavy + 6 medium + 4 light + 2 reserve)
  • Alternativas: 10 AMR (subóptimo), 20 AMR (sobredimensionado)
  • Score 15: 87/100
  • Razón: Cobertura completa de todos los flujos con 15-20% de margen

DR-004: Highway Bidireccional A+B

  • Decisión: Carril A (→) + Carril B (←) segregados
  • Alternativas: Single bidireccional, múltiples carriles especializados
  • Score A+B: 91/100
  • Razón: Simplifica traffic controller, previene deadlocks, maximiza throughput
